## 一、系统架构分析

### 1.1 核心选股逻辑

系统采用**规则 + AI 门控 + 期望值过滤**的三层筛选机制：

#### 第一层：规则引擎（技术面评分）
```python
composite_score = (
    trend_score * 0.3 +      # 趋势对齐
    reversion_score * 0.3 +  # 均值回归
    volume_score * 0.2 +     # 量能确认
    pattern_score * 0.2      # 形态识别
) * timeframe_alignment_score
```

**信号类型**:
- **左侧交易** (均值回归):
  - `signal_pullback`: 布林带极度下杀反弹
  - `signal_rebound`: 超卖恐慌底部
  
- **右侧交易** (趋势突破):
  - `signal_trend_breakout`: 均线放量金叉（仅牛市）

#### 第二层：AI 门控
- 使用 LightGBM 模型预测未来 N 天盈利概率
- 动态阈值调整（0.30-0.65）根据市场状态
- 支持集成模型（LightGBM+XGBoost+CatBoost）

#### 第三层：期望值过滤
```python
EV = (AI_prob * 目标收益 - (1-AI_prob) * 止损 - 交易成本) * 100
```
只允许 EV > 0 的交易通过

### 1.2 市场状态分类（10 类）

```
牛市：bull_momentum, strong_bull, bull_volume, weak_bull
震荡：sideways_low_vol, sideways_high_vol
熊市：weak_bear, bear_momentum, bear_panic, strong_bear
```

### 1.3 自适应参数调整

根据市场状态动态调整：
- AI 概率阈值
- 仓位大小（0.01-0.20）
- 止损/止盈倍数
- 持仓周期（2-15 天）

## 二、反向验证方案设计

### 2.1 验证逻辑

```
选择历史日期 T 
  ↓
执行选股策略 → 得到推荐股票列表
  ↓
观察 T+N 天后的表现
  ↓
统计胜率、平均收益、最大回撤
  ↓
评估选股能力
```

### 2.2 关键指标

**核心指标**:
- 胜率（Win Rate）: 盈利交易占比
- 盈亏比（Profit Factor）: 总盈利/总亏损
- 夏普比率（Sharpe Ratio）: 风险调整后收益
- 平均收益（Avg PnL）
- 利润留存率：实现收益/最大浮盈

**评估标准**:
- 优秀：胜率≥55% 且 盈亏比≥1.3
- 良好：胜率≥50% 且 盈亏比≥1.1
- 一般：胜率≥45%
- 较差：胜率<45%

### 2.3 验证工具

创建了以下验证脚本：

1. **`quant/app/reverse_validation.py`**: 完整的反向验证模块
2. **`scripts/run_reverse_validation.py`**: 多日期批量验证
3. **`scripts/quick_reverse_test.py`**: 快速测试（纯规则引擎）
4. **`scripts/single_date_test.py`**: 单日验证
5. **`scripts/full_system_validation.py`**: 完整系统验证（含 AI 训练）

## 三、AI 模型重新训练

### 3.1 问题发现

原始 AI 模型文件 (`models/alpha_lgbm.txt`) 损坏，导致：
- LightGBM 加载失败
- 错误信息：`Model format error, expect a tree here`
- 无法进行 AI 门控筛选

### 3.2 解决方案

删除损坏模型，使用 `main.py train-ai` 重新训练：

```bash
python main.py train-ai
```

**训练流程**:
1. 从历史数据构建数据集（1435 只股票）
2. 提取技术面特征（60+ 个）
3. 创建目标变量（未来 N 天是否盈利）
4. 训练 LightGBM 分类模型
5. 保存至 `models/alpha_lgbm.txt`

**预计训练时间**: ~30-40 分钟（1435 只股票）

## 四、发现的问题与优化建议

### 4.1 模型文件损坏

**问题**: AI 模型文件损坏，无法加载

**影响**: 
- 选股时无法使用 AI 门控
- 退化为纯规则引擎
- 选股质量下降

**解决**: 重新训练模型（进行中）

### 4.2 信号检测过于严格

**发现**: 在测试中发现，某些日期扫描 100-200 只股票仅发现 0-2 个信号

**原因**:
- 多层过滤（规则+AI+EV）门槛过高
- 市场状态判断可能过于保守
- 信号 cooldown 机制可能过度抑制

**建议**:
1. 调整 `min_composite_score` 门槛
2. 优化信号 cooldown 天数
3. 在不同市场状态下使用不同的过滤强度

### 4.3 量价关系优化空间

**当前配置**:
```yaml
vol_up_ratio: 1.55  # 放量门槛
vol_slope_score_weight: 0.0  # 量能斜率权重为 0
```

**建议**:
1. 增加量能斜率权重 (`vol_slope_score_weight` 从 0 提高到 0.1-0.2)
2. 区分左侧/右侧交易的量能要求
3. 考虑相对成交量（vs 20 日均量）而非绝对放量

### 4.4 趋势确认优化

**当前逻辑**: 
- 仅使用大盘指数判断市场状态
- 多周期确认可能过度过滤

**建议**:
1. 增加行业/板块趋势确认
2. 优化多周期一致性阈值
3. 考虑个股相对强度（RS vs 大盘）

### 4.5 止盈止损策略

**当前配置**:
```yaml
ai_target_atr_mult: 2.0  # 目标止盈
ai_stop_loss_atr_mult: 1.5  # 止损
trail_atr_mult: 2.0  # 移动止损
```

**建议**:
1. 根据市场状态动态调整止盈/止损比
2. 牛市：放宽止盈（2.5-3.0 ATR），收紧止损（1.2-1.5 ATR）
3. 熊市：收紧止盈（1.5-2.0 ATR），放宽止损（1.5-2.0 ATR）

## 七、关键发现

### 7.1 系统优势

1. **多层过滤机制**: 规则+AI+EV 三重筛选，避免单一维度误判
2. **市场自适应**: 10 类市场状态，动态调整参数
3. **风险约束**: ATR 为基础的动态止损，期望值过滤
4. **多周期确认**: 日线 + 周线双重验证

### 7.2 潜在问题

1. **过度过滤**: 可能导致信号过少，错失机会
2. **模型依赖**: AI 模型质量直接影响选股效果
3. **参数敏感**: 部分阈值设置可能过度拟合

### 7.3 优化方向

1. **平衡过滤强度**: 在保证质量的前提下增加信号数量
2. **增强量价分析**: 提高量能斜率、相对成交量的权重
3. **动态止盈止损**: 根据市场状态和个股波动率调整
4. **分散风险**: 增加行业/板块分散度控制

---

## 八、结论

当前选股系统具备完整的规则引擎和 AI 门控能力，架构设计合理。主要问题在于 AI 模型文件损坏导致功能受限。

**核心建议**:
1. 完成 AI 模型重新训练
2. 通过反向验证评估实际选股能力
3. 基于验证结果微调关键参数
4. 在实盘前进行大样本历史回测

**预期效果**:
- 胜率：50-60%（合理参数下）
- 盈亏比：1.2-1.5
- 夏普比率：0.8-1.5（年化）
